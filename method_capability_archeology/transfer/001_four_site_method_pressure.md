### Four-site correction

```text

→ reduce claim strength where relations are absent
```

Do not require every repository to instantiate the richer sites' evidence architecture.

## D3 — current necessity is not historical trigger

Current CLI tests call PDF generation directly, so browser installation is currently necessary for the test job.

That does not establish which historical event caused the browser-install step to be added.

### Portable distinction

```text
CURRENT NECESSITY
    why a relation matters in the present object

HISTORICAL TRIGGER
    what event/pressure caused the relation to enter
```

Either may be recoverable without the other.

This is a fourth-site strengthening of chronology/topology != causality/authority.

## D7 — negative knowledge splits into operative and genealogical forms

Three-site transfer T7 was:

```text
failure / counterexample
→ disposition
→ changed object or standing
→ compact current guard / discriminator
→ deep failure trace retained for challenge
```

Site D preserves:

```text
changed object
→ current guard/discriminator
```

Examples:

```text
libasound2t64-or-libasound2 branch
explicit Puppeteer Chrome materialization
workspace lock reconciliation
```

It does not preserve, through the searched routes:

```text
exact failure
formal disposition
rejected alternatives
historical reopening condition
```

### Four-site correction

Split the function:

```text
OPERATIVE NEGATIVE KNOWLEDGE
    current constraint/guard shaped by a failure class

GENEALOGICAL NEGATIVE KNOWLEDGE
    recoverable failure + disposition + alternatives + reopening basis
```

Sites A–C strongly preserve both. Site D strongly preserves the first and weakly/UNKNOWN the second.

### Revised portable relation

```text
failure-sensitive knowledge
→ changed object / standing
→ current guard / discriminator
```

Where richer traces survive, add:

```text
disposition
challenge route
deep failure trace
```

Do not require those as universal residence conditions.

## D8 — challengeability can become executable rather than genealogical

When original rationale is unavailable, a current guard can still sometimes be challenged by perturbation:

```text
remove / alter guard
→ run executable surface
→ observe whether invalid condition recurs
```

This is not equivalent to replaying the original historical defect. It tests the current necessity of the guard.

### Four-site correction

Challenge routes now split:

```text
GENEALOGICAL CHALLENGE
    reopen original evidence/disposition

EXECUTABLE CHALLENGE
    perturb current guard and test current consequence
```

A mature method should name which route is actually available.

## Four-site method delta

The twelve-step three-site procedure remains useful after these changes:

```text
0. Locate both boundaries:
       current authority/service edge
       archive horizon / earliest warranted historical edge
1. Recover the current authority/service graph actually present.
2. Bound one consequential formation question.
3. Recover predecessor standing/basis where surviving substrate supports it.
4. Seek pressure/failure/input; preserve trigger UNKNOWN when absent.
5. Separate evidence from authority-to-grant-standing where that distinction exists.
6. Assign inferential ceiling per load-bearing relation, not only per artifact.
7. Follow the consequential referent across representation changes.
8. Distinguish object/state movement, current necessity and improved observation.
9. Recover transition/disposition/admission at the strongest source-native level available.
10. Recover current negative knowledge as guard/discriminator; recover genealogy separately where possible.
11. Compare current compression with the recoverable pathway and archive horizon.
12. Transfer only relations that survive source-native reconstruction in the recipient.
```

This remains an interrogation order, not a universal repository schema.
